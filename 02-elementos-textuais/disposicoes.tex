\chapter{MATERIAIS E MÉTODOS}
\label{chap:materiais-e-metodos}

Este capítulo apresenta os materiais e métodos utilizados no desenvolvimento do IncluiEdu. Inicialmente, são descritos os materiais e o ambiente de desenvolvimento, contemplando as duas configurações tecnológicas adotadas: a etapa inicial, executada localmente com Python, Django, SQLite e Ollama, e a versão atual, baseada em JavaScript e TypeScript, com backend em Cloudflare Workers, banco relacional Cloudflare D1 e geração de atividades por meio do Workers AI com o modelo Gemma. Em seguida, apresenta-se a metodologia de desenvolvimento, organizada em etapas de definição das funcionalidades pedagógicas, modelagem das informações, implementação dos recursos e verificações manuais da aplicação. Na sequência, são especificados os requisitos funcionais e não funcionais do sistema, com ênfase nas ações do professor e na proteção dos registros pedagógicos. A modelagem do sistema é apresentada por meio dos diagramas de casos de uso e de classes, do modelo relacional do banco de dados e da prototipagem da interface. Posteriormente, descreve-se a implementação do sistema, abrangendo a comunicação entre interface e backend, os mecanismos de autenticação, o controle de acesso e o acompanhamento pedagógico. Por fim, são relatados os testes e a validação manual das funcionalidades, bem como a implantação da aplicação e as condições necessárias para sua reprodutibilidade.

\section{MATERIAIS E AMBIENTE DE DESENVOLVIMENTO}

O desenvolvimento do IncluiEdu envolveu duas configurações tecnológicas distintas. Na etapa inicial, executada localmente, foram utilizados Python, com requisito mínimo de versão 3.10, o framework Django e o banco de dados SQLite para armazenamento das informações. O arquivo de dependências dessa implementação especifica o Django na faixa de versões 6.0 até antes da 7.0. Para a integração inicial com Inteligência Artificial, foi utilizado o Ollama, permitindo a execução local de modelos de linguagem.

Posteriormente, a aplicação passou a utilizar uma arquitetura baseada em serviços da Cloudflare, desenvolvida em JavaScript e TypeScript, com interface construída em HTML e CSS. O backend utiliza Cloudflare Workers para processar requisições HTTP, enquanto o banco de dados relacional Cloudflare D1 é responsável pelo armazenamento dos registros \cite{cloudflare2026d1}. A comunicação entre a interface e a API utiliza dados estruturados no formato JSON.

A geração de atividades pedagógicas é realizada pelo Cloudflare Workers AI \cite{cloudflare2026workersai}, utilizando o modelo de linguagem Gemma 4 26B A4B IT (\texttt{@cf/google/gemma-4-26b-a4b-it}) \cite{cloudflare2026gemma}. Para a geração de imagens complementares às atividades, é utilizado o modelo FLUX.1 Schnell (\texttt{@cf/black-forest-labs/flux-1-schnell}).

O gerenciamento e a implantação da aplicação são realizados por meio da ferramenta Wrangler, na versão 4.129.0, registrada no arquivo \texttt{package-lock.json}. O arquivo \texttt{wrangler.jsonc} concentra as configurações do Worker, incluindo os vínculos com o banco de dados, o serviço de Inteligência Artificial e os arquivos da interface. O desenvolvimento também utiliza Node.js, com requisito mínimo de versão 18, e npm para gerenciamento das ferramentas de desenvolvimento.

O código-fonte é mantido no GitHub, utilizando o Git para controle de versões e organização das alterações realizadas durante o desenvolvimento.

\section{METODOLOGIA DE DESENVOLVIMENTO}

O desenvolvimento do IncluiEdu foi organizado em etapas, iniciadas pela definição das funcionalidades pedagógicas e pela modelagem das informações. Na primeira fase, a aplicação foi executada localmente com Django, SQLite e Ollama. Posteriormente, foi desenvolvida a versão atual, publicada na Cloudflare, com JavaScript, TypeScript, D1 e Workers AI. Ao longo do desenvolvimento, foram realizadas verificações manuais das funcionalidades.

A definição das funcionalidades considerou a necessidade de organizar turmas e alunos, registrar observações pedagógicas e apoiar o professor na elaboração de atividades personalizadas. Após a definição dos requisitos, foram elaborados modelos do sistema e implementados os recursos de autenticação, controle de acesso, acompanhamento e integração com a IA. A validação foi conduzida por verificações manuais da aplicação.

\section{IMPLEMENTAÇÃO DO SISTEMA}

Na versão atual do IncluiEdu, a interface web apresenta as telas de cadastro, consulta e acompanhamento dos alunos. As ações realizadas pelo professor são enviadas à API por meio de requisições \texttt{fetch}, utilizando dados em formato JSON. O Cloudflare Worker recebe essas requisições, verifica a sessão e as permissões do usuário e realiza as operações necessárias no banco de dados D1. Em seguida, a resposta é enviada à interface, permitindo a atualização das informações apresentadas.

A autenticação utiliza derivação de senhas com PBKDF2, \textit{salt} e SHA-256, evitando o armazenamento das senhas em texto simples. Após o login, o sistema cria uma sessão identificada por um \textit{cookie} configurado com os atributos \texttt{HttpOnly}, \texttt{Secure} e \texttt{SameSite=Strict}. O \textit{backend} também verifica se os registros acessados pertencem ao professor autenticado antes de permitir consultas ou alterações.

No acompanhamento pedagógico, cada registro reúne informações sobre o aluno, a área acompanhada, a habilidade observada, o nível de autonomia e as evidências registradas pelo professor. Esses dados são preservados no histórico pedagógico, permitindo acompanhar as observações realizadas ao longo do tempo. A situação do aluno também pode ser atualizada entre as opções Acompanhar, Requer atenção e Evoluindo.

A geração de atividades pedagógicas adaptadas é realizada por meio do Cloudflare Workers AI, utilizando o modelo de linguagem Gemma 4 26B A4B IT (\texttt{@cf/google/gemma-4-26b-a4b-it}). A integração ocorre no \textit{backend} da aplicação, responsável por receber as solicitações do professor, consultar os registros pedagógicos e encaminhar as informações ao modelo de Inteligência Artificial. O processo é iniciado quando o professor seleciona um aluno, descreve a atividade desejada e informa sua duração. O sistema recupera do banco de dados Cloudflare D1 a área de aprendizagem, a dificuldade ou habilidade cadastrada e até cinco observações pedagógicas recentes do estudante. Essas observações contêm informações sobre a área acompanhada, a habilidade trabalhada, o nível de autonomia e as evidências registradas pelo docente.

Para orientar a geração, essas informações são organizadas em um \textit{prompt} estruturado, conforme apresentado no Quadro~\ref{qua:prompt-atividade}.

Os campos apresentados entre \$\{...\} são preenchidos automaticamente pelo sistema. A variável \texttt{s.area} representa a área acompanhada, enquanto \texttt{s.difficulty} corresponde à dificuldade ou habilidade cadastrada. A variável \texttt{history} reúne até cinco observações pedagógicas recentes, \texttt{requestText} contém a solicitação do professor e \texttt{duration} corresponde à duração prevista, limitada ao intervalo de 5 a 60 minutos.

A requisição ao modelo utiliza os parâmetros \texttt{temperature} de 0,65, \texttt{max\_tokens} de 1100 e \texttt{enable\_thinking} configurado como \texttt{false}. O modelo recebe as instruções em uma mensagem com papel \texttt{user} e deve retornar exclusivamente um objeto JSON contendo os campos \texttt{titulo}, \texttt{objetivo}, \texttt{orientacoes} e \texttt{atividade}. Após o recebimento, o \textit{backend} interpreta a resposta e verifica o preenchimento dos quatro campos obrigatórios. Quando a estrutura é válida, a atividade é armazenada no banco de dados com o \textit{status} de rascunho, permitindo sua revisão pelo professor. Caso ocorra uma falha na geração ou na interpretação da resposta, o sistema apresenta uma mensagem de erro.

A personalização das atividades ocorre a partir das informações pedagógicas associadas ao estudante. Dessa forma, o modelo recebe dados sobre as dificuldades, habilidades e níveis de autonomia registrados, podendo elaborar propostas com diferentes materiais, etapas e adaptações, de acordo com o contexto informado. Durante a geração das atividades, o sistema não inclui explicitamente o nome do estudante nas instruções encaminhadas ao modelo de Inteligência Artificial.

Além da geração textual, o IncluiEdu disponibiliza um recurso para produzir imagens complementares às atividades pedagógicas, correspondente ao requisito funcional RF12 e ao objetivo específico OE8. Essa funcionalidade utiliza o modelo FLUX.1 Schnell (\texttt{@cf/black-forest-labs/flux-1-schnell}), disponibilizado pelo Cloudflare Workers AI. A geração é realizada a partir de um \textit{prompt} que considera a área de aprendizagem, o objetivo pedagógico e os primeiros 700 caracteres do conteúdo da atividade, conforme apresentado no Quadro~\ref{qua:prompt-imagem}.

O recurso busca produzir ilustrações com poucos elementos, contornos nítidos e características adequadas à impressão e à utilização em atividades escolares. A geração de imagens constitui uma funcionalidade complementar à elaboração textual, oferecendo ao professor recursos visuais que podem auxiliar na apresentação dos conteúdos. Assim como ocorre com as atividades produzidas pelo modelo de linguagem, os materiais visuais devem ser avaliados pelo docente antes de sua utilização.

\section{IMPLANTAÇÃO E REPRODUTIBILIDADE}

O IncluiEdu encontra-se publicado na plataforma Cloudflare, permitindo o acesso à aplicação por meio de um navegador web. A configuração do ambiente é organizada no arquivo \texttt{wrangler.jsonc}, que estabelece os vínculos necessários para o funcionamento dos serviços utilizados.

O código-fonte do projeto é mantido em um repositório no GitHub (\url{https://github.com/PedroFonsecac137/tccfacul}). Para reproduzir a aplicação em outro ambiente, é necessário obter os arquivos do projeto, configurar os serviços da Cloudflare, preparar o banco de dados D1 e realizar a publicação da aplicação.
